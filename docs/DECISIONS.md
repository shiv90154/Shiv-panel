# Decisions
1. **Host agent** for privileged ops. web is internet-facing; docker.sock in web = root compromise. Agent exposes typed, whitelisted RPC over a unix socket/mTLS.
2. **Container per site**, files under `/srv/accounts/<account>/<site>`, cgroup limits from the package. Runtimes are images listed in a `Runtime` table.
3. **Caddy Admin API** for per-site routes + on-demand TLS (existing `tls-ask` endpoint gates issuance).
4. **PowerDNS + PostgreSQL backend**, managed via its HTTP API; `expectedRecords()` (web/src/lib/dns.ts) is the zone template; Cloudflare stays behind a `DnsProvider` interface.
5. **restic** for backups (local/S3/SFTP targets).
6. **Postfix/Dovecot read PostgreSQL directly** through a read-only, column-limited role → adding domains needs no restarts.
7. **Bcrypt `{BLF-CRYPT}` ($2y$)** mailbox hashes, verified by Dovecot and by webmail login.
8. **Webmail session** = AES-256-GCM cookie holding credentials (IMAP/SMTP need the password); 8h expiry.
9. **Tenancy**: `Account` tree + `scopeFor(session)` applied to every Prisma query; ownership FK on every resource.
10. **One login, two shells.** `/login` (username or email) for all roles; admin/reseller land in the WHM shell `/admin`, users in the cPanel shell `/cpanel`. Pages are shared, not duplicated. Old `/admin/login` redirects.
11. **admin_users folded into accounts** (same ids, role=admin). Admins are only created by bootstrap; the panel can create resellers and users. Admins cannot be suspended, terminated or impersonated through the panel.
12. **Not-found instead of forbidden** for out-of-scope ids (no existence leaks); every action does the ownership lookup before touching a record. Foreign action forms replayed with another session are refused (tested).
13. **Impersonation**: no nesting, 2 h session, re-validated on every request (actor active + still allowed), security settings locked, every action audited with the real actor.
14. **TOTP with no extra dependency** (RFC 6238 via node:crypto); secret sealed with AES-GCM at rest; last-used step stored (replay protection); recovery codes hashed, shown once via a 2-minute sealed cookie. QR via `qrcode`.
15. **Agent transport**: HTTP+JSON over a unix socket or TCP with a bearer secret, whitelist in `agent.mjs` and typed client in `web/src/server/agent.ts` (add methods in both). Zero dependencies.
16. **Enforcement is per feature**: Phase 0 enforces domain and mailbox limits; each later feature enforces its own package limit when it ships. Suspension in Phase 0 blocks panel login only.
17. **File manager jail**: every path is lexically resolved under `/srv/accounts/<account>/<site>` AND its deepest existing ancestor is realpath-checked (a tenant's own container can plant symlinks). Delete/rename/chmod never follow links, writes refuse links, unzip strips links from the extracted tree (`-n`, never overwrites). Created files are owned by the runtime uid. Files are addressed per site (`siteId`), so tenant scope = `getOwnedSite`.
18. **Tenant databases live on host MariaDB/PostgreSQL servers, not the mail stack's PostgreSQL.** One DB + one same-named user per database, privileges on that DB only. Names are `<username[:8]>_<suffix>` (the underscore + short prefix keeps them clear of system schemas); passwords are generated, `[A-Za-z0-9_-]` only (no SQL quoting surface), sealed at rest and viewable by the owner. SQL goes over stdin, never argv. Agent env: `MARIADB_CMD` (default `mariadb`, root socket), `PSQL_CMD` + `PGHOST/PGUSER/PGPASSWORD`. Panel env: `MARIADB_HOST`, `POSTGRES_TENANT_HOST` (shown as the connection host).
19. **DNS: PowerDNS on the host, driven only through the agent.** `pdns_server` with the `gpgsql` backend (its own `pdns` database, not the mail DB), API bound to 127.0.0.1 (`api=yes`, `webserver=yes`, `webserver-address=127.0.0.1`, `api-key=...`, `default-api-rectify=yes`). Records live ONLY in PowerDNS; the panel stores just a `DnsZone` ownership row (zone name globally unique; a name that is, contains or sits under another account's zone is refused, and a starter template that would embed a mail domain's DKIM key is refused unless the same account owns that domain). Agent env: `PDNS_API_KEY`, `PDNS_API_URL` (default `http://127.0.0.1:8081`), `PDNS_NS` (comma list of nameserver hostnames used for the apex NS/SOA). The agent validates record syntax (types A/AAAA/CNAME/MX/TXT/SRV/CAA/NS; TXT auto-split into 255-byte strings; apex NS/SOA and apex CNAME rejected; names cannot leave the zone; TTL 60-86400). DNSSEC = one CSK ECDSA P-256; the DS is read back from PowerDNS. Cloudflare stays as the existing push-mail-records helper, not yet a zone provider.
20. **Cron = web app schedules, agent executes in the site's container.** The web process ticks on the minute (UTC), matches 5-field cron (own parser, `lib/cron.ts`; numbers only, dom/dow OR rule, min interval 5 min, `maxCronJobs` enforced) and calls `cron.run`, which `docker exec`s `timeout -s KILL 300 sh -c <command>` as the runtime uid in the web root (after checking the container's `mailhost.account` label equals the caller). Output capped at 64 KB, last 20 runs kept per job. Jobs skip suspended accounts and non-running sites. Single web instance assumed (a claim on `running_since` prevents double runs within one DB).
21. **Backups = restic, one repository per account** at `BACKUP_ROOT/<accountId>` (default `/srv/backups`), one server-wide `RESTIC_PASSWORD` in the agent env (repos are on the same host; this protects copied files, not a rooted host). Snapshot kinds by tag: `site:<id>` (site dir, absolute path), `db:<engine>:<name>` (dump streamed to restic stdin; a failed dump's snapshot is discarded), `mail:<domain>` (`VMAIL_DIR/<domain>`, the host path of the mail volume). Restore = `restic restore --target /` (original owners kept; agent is root) for files/mail and `restic dump | mariadb|psql` for databases; the agent refuses a snapshot unless its host is the account, its tag matches and (files) its single path equals the expected jail path. The web only restores into resources the account still owns. Retention is `forget --group-by host,tags --prune` after each run. Schedule per account: daily or weekly (Sunday) at an UTC hour. Runs are long, so the web fires them in the background and records the result in `backup_runs`. Agent env: `BACKUP_ROOT`, `RESTIC_PASSWORD`, `RESTIC_CMD`, `VMAIL_DIR`, `MARIADB_DUMP_CMD`, `PG_DUMP_CMD` (+ the DB vars from #18).

## 22. Provisioning API, keys, webhooks (Phase 5)
- Keys: `shk_` + 32 random bytes, only sha256 stored; act as their owning admin/reseller with the same subtree scope as the UI (no separate permission model). Owner suspended/impersonation-only/user role = 401. Accounts are addressed by username (WHMCS-friendly), never by internal id.
- Webhooks are outbound only, HMAC-signed over `timestamp.body`, https-only, SSRF-guarded by re-resolving DNS on every delivery and refusing redirects. Best-effort (no retry queue) - billing must reconcile via the API. Deferred: retries, delivery log.
- Reseller cap is checked when a package is created/edited (not retroactively if the reseller's own package later shrinks).
